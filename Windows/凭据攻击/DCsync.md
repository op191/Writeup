**核心概念：**

### 账户被赋予了 **DCSync 权限**（全称 Replicating Directory Changes），这个权限原本是给"域控之间互相同步数据"用的，但被滥用的话，任何拥有这个权限的普通用户账户都可以**冒充域控**去向其他域控索要整个 AD 数据库的副本——这包括**所有用户的 NTLM 密码哈希**。

### 因为拥有这个特殊权限，它实际上等于拥有了**整个 AD 域的密钥**。

**怎么利用：**

直接跑 `secretsdump.py` 转储整个 AD 数据库的哈希：

bash

```bash
secretsdump.py spookysec.local/backup:'backup2517860'@10.48.130.9 -dc-ip 10.48.130.9
```

**DCSync 获取的 NTLM，就是域内所有用户的密码哈希值（NTLM Hash）。**

它相当于拿到了**整个域的“密码数据库”**，这也是为什么 DCSync 被称为“域渗透核弹级”攻击的原因。

---

### 🔑 具体拿到了什么？

通过 DCSync，攻击者可以模拟域控同步数据的操作，从域控的 **NTDS.DIT（Active Directory 数据库文件）** 中提取出以下关键信息：

- **所有用户的 NTLM Hash**：这就是用户密码的哈希值。有了它，攻击者就可以离线破解出明文密码，或者直接用它进行 **Pass-the-Hash（PtH）** 攻击，无需知道明文密码也能登录其他机器。

- **Kerberos 密钥**：包括 **krbtgt 账户的 NTLM Hash**。拿到这个，攻击者就可以伪造黄金票据（Golden Ticket），获得域内的最高权限。

- **其他敏感信息**：如用户的组策略、SID历史记录等。

---

### 🎯 为什么它这么危险？

- **无需提权**：只要攻击者掌握了域内一个**具有目录复制权限（Replicating Directory Changes）** 的账户，哪怕它只是一个普通域用户，也能直接发起 DCSync 攻击。

- **操作隐蔽**：它通过标准的 **DRSUAPI（目录复制服务远程协议）** 请求复制数据，这种流量在域控之间是日常行为，所以很难被常规安全设备检测到。

- **后果严重**：拿到数据后，攻击者可以在自己的环境中离线破解，几乎没有账号锁定风险；或者直接伪造票据，长期维持高权限，很可能会造成难以挽回的后果。
