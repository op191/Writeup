### Kerberos 在处理"不需要预认证"的账户请求时，域控会回复一个叫 AS-REP（Authentication Server Response） 的消息，这条消息里有一部分内容是用这个账户密码经过特定算法（比如 RC4-HMAC、AES）计算出来的密钥**加密的。

所以这个哈希本质是：

> 一段被"该账户密码派生密钥"加密过的**密文**，外加一些已知的固定格式信息（比如时间戳）
> 
> 它不是密码，也不是能直接拿去登录的凭据

### 你不能拿着这条哈希直接去 SMB/RDP 登录，因为它不是密码字符串，也不是可以直接传递使用的令牌（不像 NTLM 哈希那样可以做 Pass-the-Hash）。

为什么这个东西对攻击者有用

### 因为密文里包含一段**已知格式的固定内容**（比如时间戳的字节结构是可预测的），破解者可以拿着密码字典，对每个候选密码做同样的密钥派生和加密运算，看结果是否跟这段密文匹配 —— 如果匹配，就说明这个候选密码就是真密码。这个过程叫**离线爆破**，全程不用再连服务器，速度快、不会被检测、不会触发账户锁定。

**用 `hashcat -m 18200`**

**为什么是这个模式号：**

hashcat 给每一种哈希格式都分配了一个固定的编号（叫 mode），方便你告诉工具"这段密文该用哪种算法去比对"。`18200` 这个编号专门对应的就是 **Kerberos 5, etype 23, AS-REP** 这个格式 —— 也就是你现在拿到的这种以 `$krb5asrep$23$` 开头的哈希。

拆开这个前缀看，其实它自己就在告诉你用哪个模式：

```
$krb5asrep$23$svc-admin@SPOOKYSEC.LOCAL:...
   ↑           ↑
Kerberos     加密类型
AS-REP       23 = RC4-HMAC (etype 23)
```

- `krb5asrep` → 表示这是 Kerberos AS-REP 类型的哈希（对应 AS-REP Roasting 这种攻击拿到的东西）
- `23` → 表示加密类型是 **etype 23**，也就是 **RC4-HMAC**（这是比较老、比较容易被离线爆破的加密方式，AES 版本的哈希爆破速度会慢很多）

hashcat 官方文档把这个组合固定映射到了 **模式 18200**，所以只要你看到哈希是 `$krb5asrep$23$...` 这个格式开头，就直接用 `-m 18200`，不用猜。

**完整命令：**

bash

```bash
hashcat -m 18200 svc-admin.hash passwordlist.txt
```

**如果以后遇到别的 Kerberos 相关哈希，怎么知道该用哪个模式：**

记两个常用的就够了：

| 哈希前缀                | 场景              | hashcat 模式 |
| ------------------- | --------------- | ---------- |
| `$krb5asrep$23$...` | AS-REP Roasting | `18200`    |
| `$krb5tgs$23$...`   | Kerberoasting   | `13100`    |

判断方法很简单：**看哈希字符串开头那段固定标识**，hashcat 的模式号本质上就是跟这些固定格式一一对应的，不用死记硬背，用的时候查一下 `hashcat --help | grep -i krb5` 也能直接列出所有 Kerberos 相关的模式。
