一般开在139端口（老版本协议）或者是445端口（新版本协议），两个都开为了兼容系统，

文件共享：在逻辑目录，不是新建一个文件夹，在windows已存在的系统路径，挂了一个共享名字，专门给远程SMB用，它只是一个映射别名，

比如C:\     共享名是  C$   实际指向C盘根目录 

ADMIN$ 逻辑共享 实际映射物理路径C:\Windows

特殊：  IPC$   没有对应的硬盘文件夹，单纯系统逻辑虚拟通道，只负责进程通，信管道连接，不存任何文件；

上面3个是系统创建的，权限为最高权限；

还有用户手动创建的共享目录映射，权限用户自己设置；

**进去逻辑目录里，看到的就是物理文件夹的内容**，只不过需要密码才能进，不过有些是不需密码也能访问的；

# SID 和 RID 区别

## SID（安全标识符）

**给「机器 / 域 / 全局组」发的唯一身份证**

格式：`S-1-5-21-长串数字`

- 一台机器**只有一个专属机器 SID**

- 全局通用组也有固定 SID（所有电脑都一样）

  

  ```
  S-1-5-32
  ```

    Windows 内置组

  

  ```
  S-1-22-1
  ```

    Linux Samba 用户专用

作用：**定位是哪台机器、哪个全局域**

## RID（相对 ID）

**给机器内部「单个用户 / 单个组」的房间号**

常见固定：

- 500 管理员
- 501 来宾
- 1000+ 普通自建用户

作用：**在这台机器内部，区分你是哪个账号**

## 合起来完整身份

`机器SID + RID` = 全网唯一的一个用户

举例：

```
S-1-5-21-xxx-xxx-xxx -1000
```

前面是机器，最后 `-1000` 是用户房间号。

一句话总结：

**SID 定机器，RID 定账号。**

# 2 空会话 为什么空用户名、空密码也能连上？

## 先定义

空会话 = **不填用户名、不填密码**，直接连上目标的 `IPC$` 逻辑共享

## 核心 3 个原因（直白原理）

### 1. IPC$ 设计初衷就是给「局域网匿名查询」用的

IPC$ 不存文件，只做**主机间通信、网络发现**

微软 / Samba 原生设计：

**允许匿名不用登录，就能进来查基础信息**

本来就是给局域网电脑互相探身份、查工作组用的。

### 2. 服务配置默认放开匿名访客

不管老 Windows 还是靶机 Samba：

默认配置里开了：

- 允许 **匿名 Null 会话**
- 允许 **Guest 访客无密码接入**
- 不拦截空账号连接

靶机更是故意不加固，**留着给你渗透练习**。

### 3. 认证机制「放过匿名身份」

正常登录：要校验账号密码对错

空会话：

直接给你分配一个**匿名访客身份**，**不校验密码**，直接放行

虽然权限不高，但**足够枚举用户名、密码策略、工作组、SID/RID 遍历**。

## 空会话能干啥（你刚才看到的）

- 不用账号密码，连接 IPC$
- 查主机名、工作组、系统版本
- 枚举所有本地用户、用户组
- 看密码长度、是否复杂度、是否账号锁定

## 一句话讲透

**系统为了局域网互相发现，默认允许匿名连 IPC$；靶机没做安全加固，所以空用户空密码直接能进来扒所有用户信息。**

# 超精简背诵版

1. SID 是机器 / 域唯一标识，RID 是本机内部用户编号；完整账号由 SID+RID 组成。

2. 空会话能无密码连接：

   

   IPC$ 原生支持局域网匿名通信 + 系统 / Samba 默认允许匿名访客 + 未做安全策略限制，所以空账号空密码可建立会话，用来枚举用户和策略。
