**SID = Security Identifier（安全标识符）**

Windows 系统里用来唯一标识一个"安全主体"的编号 —— 这里的"安全主体"可以是用户、组、计算机，甚至整个域本身。可以理解成 Windows 世界里的"身份证号"，作用类似于 Linux 里的 UID/GID，但格式更复杂。

**格式长这样：**

```
S-1-5-21-3591857110-2884097990-301047963
```

拆开看：

- `S`：表示这是一个 SID
- `1`：版本号，固定的
- `5`：权威机构标识（5 代表 NT Authority，也就是 Windows 安全体系）
- `21`：表示这是一个"域级"或"本地计算机级"的 SID
- `3591857110-2884097990-301047963`：这一串数字才是真正唯一标识这个域的部分，每个域装的时候随机生成，全球唯一

**这个域 SID 是"半成品"，后面加上 RID 才是完整用户 SID**

域本身的 SID 后面还会加一段叫 **RID（Relative Identifier，相对标识符）**，用来标识域里具体的某个用户或组。比如：

```
S-1-5-21-3591857110-2884097990-301047963-500
```

最后的 `-500` 就是 RID，`500` 在 Windows 里是固定含量 —— 永远代表 **内置的 Administrator 账户**（不管账户改没改名字，RID 500 永远是那个真正的管理员）。常见的固定 RID 还有：

- `500` = Administrator
- `501` = Guest
- `512` = Domain Admins 组
- `1000` 往后 = 后来创建的普通用户/组，依次递增

**为什么拿到域 SID 有用：**

拿到了域 SID 前缀之后，就可以通过 **RID 爆破（RID cycling）** 的方式，把 500、501、1000、1001... 依次拼上去，去问域控"这个 SID 对应的用户名是谁"，即使 RPC 拒绝了直接列用户名的请求，很多时候单独查某个 SID 对应的用户名反而不会被拒绝。这也是为什么工具会优先想办法拿到这个域 SID。
