# Docker 网络完整梳理

## 一、核心架构

Docker 采用 *****（Container Network Model）容器网络模型 **，三层结构：

1. **沙盒 Sandbox**：容器网络栈（网卡、路由、DNS、iptables，隔离）
2. **端点 Endpoint**：veth 虚拟网卡，连接容器与网桥
3. **网络 Network**：一组互通的端点集合

底层依赖 Linux 内核组件：`veth pair`、`bridge`、`iptables`、`net namespace`、路由转发。

## 二、Docker 5 种内置网络驱动

### 1. bridge（默认桥接,不将物理网卡桥接到虚拟网卡）（这里的桥接是NAT，真正的桥接是macvlan)

- 新建容器不加 `--network` 自动接入 `docker0` 网桥
- 原理：宿主机虚拟网桥 `docker0`，每个容器一对 veth 网卡，一端进容器 netns，一端挂网桥
- 网段默认 `172.17.0.0/16`
- 互通规则：
    
    - 同网桥容器互相直连通信
    # - 容器访问外网：SNAT 源地址转换，走宿主机网卡上网(流量从虚拟网卡到物理网卡这个过程被做了手脚)
    - 外部机器无法主动访问容器，需 `-p 端口映射`（DNAT）（因为外部流量走到物理网卡，物理网卡不会给流量通到虚拟网卡）
    
- 自定义 bridge：`docker network create 子网名字`，隔离不同业务容器

### 2. host 主机网络

- 容器**不创建独立网络命名空间**，直接复用宿主机网卡、IP、端口
- 优点：无端口转发损耗，性能高
- 缺点：无网络隔离，端口不能冲突；容器直接暴露宿主机所有网络服务
- 使用场景：高性能需求（监控、网关）

### 3. none 无网络

- 容器只有 lo 本地回环网卡，无任何外部网络
- 完全隔离，不能访问其他容器、外网
- 场景：纯本地计算、安全隔离任务

### 4. container 复用其他容器网络

- 新容器共享已有容器的 net namespace、IP、网卡
- 两者端口互通，共用一套网络栈
- 典型场景：sidecar 配套容器（日志采集、代理）

bash

运行

```
docker run --network container:目标容器ID xxx
```

### 5. overlay 覆盖网络（多主机集群）

- Swarm 集群专用，跨多台宿主机容器互通
- 底层 VXLAN 隧道封装，跨节点容器如同在同一局域网
- 分两种：
    
    - ingress：集群负载均衡，对外暴露服务
    - user-defined overlay：业务容器互通内网
    

## 三、关键底层组件

1. **veth pair**
    
    成对虚拟网线，一端容器、一端网桥，实现容器内外数据转发。
2. **docker0 网桥**
    
    默认虚拟交换机，所有默认容器接入，负责二层转发。
3. **iptables 规则**
    
    Docker 自动维护 NAT / 转发链：
    
    - `-p 宿主机端口:容器端口`：DNAT 端口映射
    - 容器访问外网：POSTROUTING SNAT
    - 隔离不同自定义网桥流量
    
4. **端口映射 -p**
    
    两种写法：
    
    - `-p 8080:80` 宿主机 8080→容器 80
    - `-p 127.0.0.1:8080:80` 仅本机可访问
        
        原理：iptables DNAT 转发流量到容器 IP
    

## 四、容器间通信三种方式

1. 同自定义 bridge：直接容器名 DNS 互通（Docker 内置 DNS 解析）
2. host 网络：[localhost](https://link.wtturl.cn/?target=https%3A%2F%2Flocalhost&scene=im&aid=497858&lang=zh "autolink") 互访
3. overlay 网络：跨宿主机容器互通

## 五、外部访问容器

1. 端口映射 `-p`（单机 bridge 标准方案）
2. host 网络直接占用宿主机端口
3. Swarm ingress 负载均衡（集群）
4. 反向代理 Nginx/Traefik 转发到容器内网 IP

## 六、网络常用命令

bash

运行

```
# 查看所有网络
docker network ls
# 查看网络详情（网段、挂载容器）
docker network inspect 网络名
# 创建自定义桥接网络
docker network create my-bridge
# 容器接入指定网络
docker run --network my-bridge xxx
# 容器动态加入/移出网络
docker network connect/disconnect
```
