### `-sS`：SYN 隐身扫描（TCP SYN Scan）

这是 Nmap **默认**且最经典的扫描方式，也被称为“半开扫描”（Half-open scanning）。

#### 工作原理

它利用了 TCP 建立连接时的“三次握手”过程，但**不完成**它：

1. 客户端（你）发送一个 **SYN** 包给目标端口。
    
2. **如果端口开放**：目标会回复 **SYN-ACK**。这时，客户端**不发送最后的 ACK**，而是直接发送 **RST** 包重置连接。
    
3. **如果端口关闭**：目标会回复 **RST** 包。
    

#### 为什么叫“隐身”？

因为它**没有完成完整的三次握手**，所以很多应用程序（如 Web 服务器、数据库）不会在日志中记录这次连接尝试。但对于现代防火墙和 IDS/IPS 来说，`-sS` 的扫描特征非常明显，它们能轻易识别这种模式。

#### 优点

- **速度快**：比全连接扫描（`-sT`）更快。
    
- **日志痕迹少**：目标应用层服务通常不会记录这次连接，因为连接没建立起来。
    

#### 缺点

- 需要 **root/管理员权限** 才能构造原始 SYN 包。
    
- 现代防火墙和 IDS 能轻松检测到这种扫描模式。

### 🕵️ `-sA`：ACK 扫描（TCP ACK Scan）(专门用于探测防火墙规则)

这个扫描不直接告诉你端口是“开放”还是“关闭”，而是用来**探测防火墙的过滤规则**。

#### 工作原理

它发送一个 **ACK** 包（而不是 SYN 包）。在正常的 TCP 通信中，ACK 包只在连接建立后才会出现。所以，目标系统收到一个孤立的 ACK 包时：

- **如果防火墙没有过滤该端口**：目标会回复一个 **RST** 包，告诉发送方“这个连接不存在”。Nmap 会将该端口标记为 **`unfiltered`**（未过滤）。
    
- **如果防火墙过滤了该端口**：防火墙会直接丢弃这个 ACK 包，Nmap 收不到任何回复，将该端口标记为 **`filtered`**（被过滤）。
    

#### 这个扫描的价值在哪？

它无法告诉你端口是否开放，但能帮你**绘制防火墙的规则地图**。例如：

- 如果 80 端口返回 `unfiltered`，说明防火墙允许通过；如果 443 端口返回 `filtered`，说明防火墙对该端口做了限制。
    
- 结合 SYN 扫描（`-sS`）和 ACK 扫描（`-sA`）的结果，可以推断出防火墙的配置策略：
    
    - SYN 显示 `open`，ACK 显示 `unfiltered` → 端口开放，且未被防火墙拦截。
        
    - SYN 显示 `filtered`，ACK 显示 `filtered` → 防火墙大概率丢弃了所有包。
        
    - SYN 显示 `filtered`，ACK 显示 `unfiltered` → 存在一个“无状态”防火墙，只拦截 SYN 包，不对 ACK 包做限制。
        

#### 缺点

- 它需要 root/管理员权限。
    
- 现代“状态防火墙”（Stateful Firewall）能识别出孤立的 ACK 包并直接丢弃，使得 `-sA` 的效果大打折扣，返回的结果会和 `-sS` 一样全是 `filtered`。

### 📊 对比总结

| 对比维度          | `-sS` (SYN扫描)       | `-sA` (ACK扫描)      |
| ------------- | ------------------- | ------------------ |
| **主要目的**      | 判断端口是否开放            | 判断防火墙是否过滤了该端口      |
| **发送的包**      | SYN                 | ACK                |
| **开放端口的响应**   | SYN-ACK → 你发 RST 终止 | RST (目标告诉你“连接不存在”) |
| **关闭端口的响应**   | RST                 | RST                |
| **被防火墙过滤的响应** | 无响应，标记为 `filtered`  | 无响应，标记为 `filtered` |
| **权限要求**      | root                | root               |
| **日志可见性**     | 较低（应用层通常不记录）        | 很低（但防火墙会记录）        |
| **是否能绕过防火墙**  | 不能，但能绕过某些无状态防火墙     | 专门用于探测防火墙规则        |
|               |                     |                    |
