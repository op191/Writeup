# 本地转发

你本地访问A，SSH帮你通过跳板机转给目标B。

**场景**：公司防火墙只让连跳板机，你想访问内网数据库。命令：`ssh -L 本地端口:目标IP:目标端口 跳板机用户@跳板机IP`。执行后，你访问自己电脑的`本地端口`，流量就加密到达目标了。

```
ssh -L 8888:192.168.1.100:80 root@123.123.123.123
```

# **远程转发（反向隧道）**：把服务器的端口“搬”到你本地来。

**场景**：你在家想远程帮公司服务器装软件，但服务器没公网IP。在服务器上执行：`ssh -R 远程端口:本地IP:本地端口 你家里有公网IP的电脑`，这样访问你家里电脑的`远程端口`，就连回了服务器

```
ssh -R 8080:127.0.0.1:3000 root@123.123.123.123
```

# **动态转发（Socks代理）**：不指定目标，变成一个**加密的万能代理（SOCKS5）**。

**场景**：在咖啡厅用公共WiFi，想所有上网流量都加密。命令：`ssh -D 本地端口 
 用户@跳板机ip`，然后在浏览器或系统网络设置里，把代理地址填`127.0.0.1:本地端口`，所有请求都走加密隧道了。

```
 ssh -D 9524 pp@10.25.46.12
```

### 对比各种组合

| 命令                  | 效果       | 适用场景   |
| ------------------- | -------- | ------ |
| `ssh user@host`     | 登录Shell  | 正常远程管理 |
|                     |          |        |
| `ssh -fN user@host` | 后台转发，不登录 | 持久化隧道  |
| `ssh -f user@host`  | 后台登录     | 执行后台任务 |

-f是用来让ssh后台运行的 如果有-N参数，即不开启登陆shell,那么终端就会卡住，因为当前终端被ssh占用了，但是你又不开启登陆shell,所以输入啥都没有用，如果关闭终端就会ssh进程关闭，隧道关闭

##### -fN 参数需要一起用
